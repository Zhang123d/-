# GCG：从自动搜索一段后缀，到跨模型迁移

[首页](../README.md) · [研究背景](../jailbreak-background/README.md) · [Causal Analyst](../causal-analyst/README.md) · [TRAP](../trap/README.md) · [Best-of-N](../best-of-n/README.md) · [DUALBREACH](../dualbreach/README.md) · **GCG**

> **论文：** *Universal and Transferable Adversarial Attacks on Aligned Language Models*<br>
> **作者：** Andy Zou、Zifan Wang、Nicholas Carlini、Milad Nasr、J. Zico Kolter、Matt Fredrikson<br>
> **版本：** arXiv v2，2023-12-20，共31页 · [论文](https://arxiv.org/abs/2307.15043v2) · [代码](https://github.com/llm-attacks/llm-attacks)

## 模型会拒绝，搜索也可能还不够强

直接提出有害请求，模型通常会拒绝。但人们已经发现，改变表达方式有时会改变回答。作者进一步追问：能否让程序自动找到这样的输入，而且换个问题、换个模型后仍然有效？

他们选择保留原问题，在后面追加一段可以搜索的文本，称为**攻击后缀**。它不必像自然语言，也不修改模型参数；真正要寻找的是一段能改变模型回答倾向的输入。[论文§1–2，pp.3–6][background]

## 梯度负责指路，实际损失负责选定

困难在于文字是离散的：换一个token，就是换一个模型处理的文字单位，无法像像素那样连续微调；逐一尝试所有替换，计算量又太大。

作者提出 **Greedy Coordinate Gradient（GCG）**，把搜索分成两步：先用梯度为后缀各位置筛出有希望的替换，再对抽取的候选实际计算损失，选定本轮替换。优化目标是让模型更可能生成**包含原任务内容的肯定式回答开头**，而不是仅仅出现一个通用的“Sure”。[§2.1–2.2，pp.5–7][algorithm]

```mermaid
flowchart LR
    A[问题与待优化后缀] --> B[梯度筛选候选]
    B --> C[实际计算候选损失]
    C --> D[选定本轮替换]
    D -->|继续搜索| A
    D -->|搜索结束| E[得到攻击后缀]
```

关键是：**梯度只是局部线索，最后仍需实际评估**。GCG每轮会考虑多个可修改位置，但每个候选通常只替换一个token，不能理解成同时重写整段。它结合了已有离散优化思路，贡献在于有效的搜索组合与后续泛化验证，而非每个组成都是首次提出。

## 找到一次有效的输入，还不叫“通用”

如果每个问题都要重新搜索，就仍是逐题攻击。作者于是让**同一段后缀在多个问题上共同优化**，再把它用于未参与搜索的问题；进一步，在多个源模型上共同优化，测试效果能否迁移到其他模型。

标题中的两个词由此分开：**通用（Universal）是跨问题复用，可迁移（Transferable）是跨模型起作用**。前者不自动保证后者，两者也都不意味着适用于任意问题和模型。[§2.3、§3，pp.8–13][transfer]

跨任务实验中，作者用25条行为优化共享后缀，在另外100条行为上测试；GCG在Vicuna和Llama-2上的测试成功率分别为98%和84%。这说明后缀的效果不限于优化时见过的问题。[表1，pp.10–11][tasks]

## 开源模型上的搜索，影响到了黑盒目标

更受关注的结果来自迁移实验。作者在开源模型上优化后缀，再将文本提交给未直接参与优化的模型，**没有使用GPT-4的梯度训练后缀**。

在388条测试行为上，v2表2中GPT-4仅接收原问题时的成功率为8.0%；使用Vicuna上优化的GCG后缀时为34.5%，该行取两条后缀中更好的整体结果。依次尝试多条后缀及其拼接版本、任一成功即计成功的集成方式，则达到46.9%。**最后一个数字是一组候选的覆盖率，不能当作单条后缀的一次成功率**。这些结果对应论文当时的模型快照。[§3.2、表2，pp.12–14][results]

不过，本地优化也有边界：图6显示，源模型上的目标损失继续下降时，黑盒迁移效果可能先升后降。作者将其解释为潜在过拟合。**越适合源模型，不一定越能迁移到陌生模型**。[图6、§3.3，pp.16–17][limits]

## 这篇论文真正推进了什么

GCG把依赖人工经验的越狱文本，变成了可以自动搜索、比较并检验泛化的对象。它的证据分成三层：先证明搜索有效，再证明跨问题复用，最后证明部分跨模型迁移。三层结果应分别阅读，不能只用一个最高成功率概括。

我的阅读启发是：**拒绝直接请求，只能说明模型挡住了这种输入；判断防御是否稳健，还要看它能否经受更强搜索与未见攻击**。但本文没有给出完整有效的新防御方案，也没有证明所有模型都同样脆弱。

联系后续工作，[Best-of-N](../best-of-n/README.md) 用随机增强扩大尝试，[TRAP](../trap/README.md) 用历史反馈选择策略，[DUALBREACH](../dualbreach/README.md) 将护栏与模型共同纳入优化。GCG提供了另一条基础路线：利用可访问模型的梯度搜索离散文本，再检验复用与迁移。它们的成功率仍需在统一模型、预算和判分口径下比较。
